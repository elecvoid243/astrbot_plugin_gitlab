# PR-Agent 的大型 MR 评审行为

核查对象为开源 PR-Agent 的 GitLab webhook 和 `/review` 路径。源码固定在 2026 年 11 月 27 日核对的上游 main 提交 `2f7d15923cdea60e9fa0524f9839fbc1632c55b8`。从 0.51 起，`/improve` 和 `/improve_code` 都执行 `/review`。 [上游提交](https://github.com/The-PR-Agent/pr-agent/commit/2f7d15923cdea60e9fa0524f9839fbc1632c55b8) · [Improve 文档](https://docs.pr-agent.ai/commands/improve/)

## 1. 自动评审和同次调用内的重试

- `enable_large_pr_chunking` 默认关闭。开启后，如果单次模型预算遗漏文件，评审尝试按预算分块。每块独立调用模型，成功结果保存在本次评审对象内，合并为一个评审。模型失败或返回无法解析的结果时，后备模型只补做未完成的块。较小的后备模型可按文件边界细分待处理块，较大的后备模型可在容量和块数允许时补入先前遗漏的文件。后备策略耗尽时，如果有成功块，流程仍可发布部分结果。 [默认配置](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/settings/configuration.toml#L227-L233) · [分块与重试](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L1676-L1787) · [后备模型重新规划和聚合](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L1824-L1939) · [后备耗尽后的部分发布](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L927-L956) · [分块评审文档](https://docs.pr-agent.ai/commands/review/#reviewing-a-pr-that-does-not-fit-in-one-call)
- 这条路径没有跨运行的自动续跑检查点。块数上限剩下的文件列入覆盖报告。每次执行创建命令对象，评审入口也会清除已完成块和待评审块的内存记录。GitLab webhook 的打开、推送等配置触发独立命令。 [分块遗漏记录](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/pr_processing.py#L582-L606) · [命令对象创建](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/agent/pr_agent.py#L517-L528) · [清理块状态](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L836-L841) · [GitLab webhook](https://docs.pr-agent.ai/usage-guide/automations_and_usage/#gitlab-webhook)

## 2. 配额上限和实际模型请求

- `pr_reviewer.max_number_of_calls` 默认 3，只在分块评审开启时限制同次评审的分块计划。分块任务默认并行，启用适用的提示缓存时可先执行第一块。失败块可经后备模型再次调用，模型处理器本身也有重试，所以真实请求数可以超过计划块数。源码按字段合并已校验的结果，例如合并并去重发现，全局风险取较保守判断。合并本身由 Python 完成。 [默认配置](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/settings/configuration.toml#L229-L233) · [块数限制](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/pr_processing.py#L544-L561) · [并行执行](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/chunk_runner.py#L40-L92) · [模型处理器重试](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/ai_handlers/litellm_ai_handler.py#L3243-L3255) · [结果合并](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/review_merge.py#L1-L22)
- 输出中的 `total_chunks` 和 `failed_chunks` 对应后备流程结束时的分析计划。该字段无模型尝试次数。每次新触发都会重新应用设置，分块流程没有同一 MR 版本跨命令累加的请求配额。 [输出字段定义](https://docs.pr-agent.ai/commands/review/#manual-triggering) · [计数实现](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L1924-L1932) · [命令运行入口](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L836-L841)

## 3. 手动评审、增量评审和逐提交评审

- 普通手动 `/review` 发起一次新评审，对当前 MR 重新准备差异。历史发现可作为提示上下文。持久摘要和历史发现只传递评审输出，新运行会重新生成分块计划。配置启用 `skip_unchanged_diff` 后，适用的自动或 CLI 运行可跳过未变化的差异，评论触发的手动命令仍执行。 [评审入口清理块状态](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L836-L841) · [历史发现配置](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/settings/configuration.toml#L202-L213) · [跳过未变化的差异](https://docs.pr-agent.ai/usage-guide/automations_and_usage/#skipping-runs-when-nothing-changed)
- `/review -i` 以此前评审为基准，评审之后引入的变更。在 GitLab 上，找不到历史评审或无法验证提交时间线时会改做普通评审。时间线有效且没有新提交时可直接跳过。此前因 token 额度遗漏的同版本文件，不会仅凭其遗漏状态进入这次增量评审。 [参数和分支](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L477-L510) · [GitLab 增量时间线](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/git_providers/gitlab_provider.py#L947-L984)
- `per_commit_review` 默认关闭。它在 GitHub 和 GitLab 上把各提交作为独立评审单位。提交成功评审后，机器人在自己的评论中写入变更指纹，后续运行据此识别已评审的提交。此处持久记录的单位为提交，而大型 MR 分块的执行状态仅保存在相应运行内。 [默认值](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/settings/configuration.toml#L200-L207) · [逐提交评审文档](https://docs.pr-agent.ai/commands/review/#reviewing-each-commit-separately) · [逐提交记录发布](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L819-L841)

## 4. 默认覆盖范围和超大文件

- 单次请求模式在溢出时删减放不下的文件补丁。分块模式仍按文件装箱，超大单文件补丁默认按 token 裁剪，亦可设为跳过。行号渲染把删除文件表示为文件名提示，大型差异压缩也可能移除仅含删除的变更块。纯删除文件的 MR 可以因此没有可分析源码并跳过模型调用。 [单次压缩](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/pr_processing.py#L321-L353) · [超大单文件裁剪](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/pr_processing.py#L470-L535) · [删除内容处理](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/git_patch_processing.py#L382-L413) · [删除文件覆盖说明](https://docs.pr-agent.ai/commands/review/#manual-triggering)
- GitLab provider 先应用忽略规则和文件类型过滤。默认忽略规则包括 `vendor/**`，硬编码过滤包括 `package-lock.json`、`yarn.lock`、`pnpm-lock.yaml`、`uv.lock`、`go.sum` 以及部分压缩文件和 source map。更广泛的框架生成目录规则由 `ignore_language_framework` 启用。默认覆盖页脚和 CLI JSON 覆盖字段列出因预算或块数而遗漏、被裁剪及仅以文件名表示的删除文件，文件类型过滤项不计入这些列表。 [GitLab 过滤流程](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/git_providers/gitlab_provider.py#L1540-L1578) · [默认忽略规则](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/settings/ignore.toml#L5-L9) · [文件类型与锁文件过滤](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/language_handler.py#L7-L68) · [框架过滤](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/algo/file_filter.py#L43-L67) · [覆盖页脚实现](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L2285-L2301) · [JSON 覆盖说明](https://docs.pr-agent.ai/commands/review/#manual-triggering)
- GitLab provider 先读取并校验全部分页，同步检查分页前后的 MR SHA、diff refs、文件数。计数为 `1000+` 等封顶结果或与实际列表不符会拒绝使用。对于已知路径而补丁缺失的文件，读取锁定 base/head 的内容重建补丁，读取失败则标记该文件无法读取。 [分页和版本校验](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/git_providers/gitlab_provider.py#L743-L786) · [缺失补丁处理](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/git_providers/gitlab_provider.py#L1573-L1635) · [GitLab 差异 API](https://docs.gitlab.com/api/merge_requests/#list-merge-request-diffs)

## 5. GitLab 摘要和命令回复

- 普通完整评审的 `persistent_comment` 默认开启。自动和手动完整评审使用同一普通评审标识，通常编辑先前的评审摘要。摘要默认是普通 note，`gitlab.publish_review_as_thread=true` 可使新建的摘要成为可解决的讨论。已存在的普通 note 继续原地更新。 [默认值](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/settings/configuration.toml#L198-L207) · [普通评审摘要分支](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L1025-L1075) · [GitLab 摘要讨论配置](https://docs.pr-agent.ai/usage-guide/additional_configurations/#post-the-review-as-a-gitlab-thread)
- `gitlab.reply_to_trigger_comment` 默认关闭。开启且 webhook 提供讨论 ID 时，顶层评论中的 `/review` 可在触发讨论回复。如果持久摘要已在别处，新运行会更新原摘要，并在新命令讨论发摘要链接。拿不到讨论 ID 或发送回复失败时回退到普通 note。摘要更新分支根据普通评审标识和持久评论设置选择，没有要求既有摘要来自同版本自动评审。GitLab webhook 默认跳过草稿自动反馈，草稿仍可手动评论触发评审。 [GitLab 默认值](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/settings/configuration.toml#L375-L383) · [触发讨论规则](https://docs.pr-agent.ai/usage-guide/additional_configurations/#reply-to-the-triggering-gitlab-discussion) · [webhook 的讨论 ID 条件](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/servers/gitlab_webhook.py#L676-L698) · [回复实现](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/git_providers/gitlab_provider.py#L2145-L2177) · [草稿规则](https://docs.pr-agent.ai/faq/#q-can-pr-agent-review-draftoffline-prs)
- `inline_key_issues` 默认开启。行内评论成功发布或匹配已有评论时，相应发现从摘要移出。无法定位或发布的发现留在摘要。常规评审的 GitLab 行内发布会核对最新差异版本的 base/start/head，版本不匹配时跳过该行内发布。 [行内发现配置](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/settings/configuration.toml#L213-L215) · [发布规则](https://docs.pr-agent.ai/commands/review/#configuration-options) · [行内发布版本校验](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/git_providers/gitlab_provider.py#L2777-L2797)
