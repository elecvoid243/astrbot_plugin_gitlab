# 大型合并请求评审自动续跑

本页记录早期设计，现行决策见 [ADR 0004](./0004-review-merge-request-diffs-in-batches.md)。

大型合并请求需要分多批评审。单轮达到处理额度后，机器人保存同一评审版本已完成批次的结果和剩余进度，将续跑排到队尾，让其他合并请求和议题也有机会得到处理。评审完成后更新同一条摘要，项目成员无需再次触发。

每个绑定项目可设置同一合并请求版本的自动评审累计上限。每轮续跑共用该预算，以控制极大型合并请求的模型用量。额度用尽时，机器人暂停自动续跑，保留进度，并在评审摘要中列出已确认的发现、尚未覆盖的范围和暂停原因。

自动评审预算用尽后，可触发成员可以用 `/review` 在手动额度内继续评审当前版本。手动续跑复用该版本已完成的批次，从尚未完成的变更继续。

所有文本变更默认纳入评审，包括锁文件、生成文件和仓库内的第三方代码。源码、测试和配置可以先评审，剩余文本仍计入覆盖范围。摘要同时报告二进制文件等无法逐行评审的变更。

手动续跑有新结果时，如果当前版本已有自动摘要且合并请求仍满足自动评审条件，机器人更新该摘要，并在命令所在讨论回复进度和摘要链接。草稿、关闭自动评审或当前版本没有自动摘要时，机器人将结果发到命令所在讨论。
