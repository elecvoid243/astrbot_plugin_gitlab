# 大型合并请求评审采用 PR-Agent 的分块策略

早期实现为本地 Git 读取和模型入口各设置固定长度上限，大型合并请求因此只评审差异的前缀。采用 PR-Agent 单次评审内的文件选择、可选分块、预算和发布策略。按模型容量取用文件补丁，并报告本次覆盖缺口。此决策取代 ADR 0003 的跨运行续跑方案。 [PR-Agent 核查记录](../research-pr-agent-large-reviews.md)

## 评审和预算

1. 从本地 Git 镜像按 `base_sha` 和 `head_sha` 枚举改动及文件补丁。评审及源码证据固定在同一版本。收集差异后和发布前核对版本，发现版本变化时停止发布旧结果。
2. 用模型的上下文预算规划请求，为提示词、源码证据和输出留空间。整个差异放得下时作为一批。`enable_large_pr_chunking` 默认关闭，超预算时按文件缩减补丁，生成一份评审。启用分块后，按模型预算把文件补丁装入多个批次，并合并结果。
3. `max_number_of_calls` 默认 `3`，限制本次评审计划的批次数。模型重试及后备调用可以增加实际请求次数。成功批次在本次运行内保留，后备模型只重试未完成的批次。成功部分合并、去重并保留证据链接。重试耗尽时，已有成功批次则发布部分结果，全部失败则报告评审失败。
4. 自动触发和成员手动输入 `/review` 都为当前 MR 重新规划一次评审。批次进度和预算的生命周期为一次运行。

## 文件范围和覆盖报告

- 沿用 PR-Agent 的默认路径和文件类型过滤，包括 `vendor/**`、常见锁文件、压缩代码和 source map。框架生成代码的额外规则通过配置启用。
- 分块时，单个文件的补丁仍可能超出单批容量。`large_patch_policy` 默认为 `clip`，可设为 `skip`。整文件删除可以文件名提示表示。仅有这类删除且没有可分析补丁时，跳过模型评审。
- 覆盖脚注默认开启。它列出通过过滤但因预算未进入评审的文件、被裁剪的文件、仅以名称表示的删除文件及失败批次。按路径或类型排除的文件独立于这些覆盖缺口。

## GitLab 摘要

普通全量评审默认使用同一条持久摘要。自动和手动触发都可更新已有摘要，首次默认发布为普通 Note。`publish_review_as_thread` 可将新建摘要改用可解决的讨论。更新提示默认开启。`reply_to_trigger_comment` 默认关闭，开启且能定位命令所在讨论时，机器人把更新链接发到该讨论。无法定位或讨论回复失败时，发普通 Note。部分评审保留已有的发现状态，是否另发评论取决于该次结果能否安全写入持久摘要。 [PR-Agent 的 GitLab 发布配置](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/docs/docs/usage-guide/additional_configurations.md#L278-L306) · [评审发布流程](https://github.com/The-PR-Agent/pr-agent/blob/2f7d15923cdea60e9fa0524f9839fbc1632c55b8/pr_agent/commands/pr_reviewer.py#L927-L1045)

## 验收场景

- 默认配置下，超预算 MR 走单批评审，报告预算遗漏。开启分块后，能容纳更多文件，并在超过默认三批时报告剩余覆盖缺口。
- 同一版本先完成全覆盖并发布发现，随后因预算或裁剪只覆盖部分文件时，保留原摘要并另发部分结果。
- 超大单文件分别验证裁剪和跳过。常见锁文件及 `vendor/**` 走过滤，整文件删除按覆盖脚注的规则显示。
- 某批失败且后备模型可用时，只重试未完成批次。手动 `/review` 再次触发时，按当时的差异生成自己的批次计划。
- 评审期间源提交或比较基线变化时，停止发布旧结果。手动评审完成且已有摘要时，更新同一条摘要。开启讨论回复后，更新链接出现在命令讨论中。
